# Proposed package layout and toolchain

Planning only, reviewed 2 November 2026. No packages have been installed, resolved,
locked or security-tested in this stage. Host `python3` reports 3.14.7; that is not
proof that the eventual application stack is compatible. Preserve the existing
virtual environment. Stage 03 selects exact supported versions, resolves all
transitive dependencies and verifies a clean installation before committing locks.

## Runtime proposal

- Target CPython 3.13 with a supported patch version, subject to Stage 03 compatibility
  verification. Use an isolated environment and the same interpreter in CI.
- Flask 3.1 series, Jinja and Werkzeug as compatible dependencies; application
  factory, blueprints, server-rendered templates and limited JavaScript.
- Official PyMongo 4.x driver, explicit repositories, validators and indexes.
  Select a supported MongoDB server release using the driver/server/Python matrix.
  A single-node local replica set enables development transactions, not production
  availability. Separate development and test databases and restricted identities.
- Authlib is the proposed OIDC client; validate discovery, signatures, claims,
  state, nonce and S256 PKCE with negative tests in Stage 05. Review its interaction
  with server-side pre-authentication/session state. Do not copy examples using
  client-side token storage. Choose and pin an isolated OIDC provider in Stage 03;
  no local-password application fallback or public self-registration.
- Evaluate Flask-WTF/WTForms for forms/CSRF and an established server-side session
  integration against ADR-05's hashed opaque tokens. No custom cryptography or
  assumption that an extension alone satisfies the session contract.
- Gunicorn for the production WSGI target; separate polling worker and local-only
  email capture. Container Compose proposal for isolated dependencies. No real email.

## Development and verification proposal

Use `pyproject.toml` for metadata/tool configuration and a reproducible lock with
hashes generated by a maintained resolver selected in Stage 03. Separate runtime
and development dependencies. Candidate tools: pytest, Ruff, coverage,
Playwright, axe-core, pip-audit, Gitleaks, OWASP ZAP and Locust. Check each tool's
primary documentation, support, licence and compatibility before adoption; these
are proposals rather than assertions of currently verified versions. Pin tools and
container digests when introduced. Do not implement empty test suites now.

## Layout

| Location | Planned responsibility |
| --- | --- |
| `app/__init__.py`, `app/config.py` | Factory, explicit environment validation (Stage 03) |
| `app/auth/`, `app/policies/` | Identity/session boundary and central resource policies |
| `app/cases/`, `communications/`, `referrals/`, `admin/`, `audit/` under `app/` | Feature routes/forms and explicit response projections |
| `app/services/` | Domain rules, transaction coordination, audit-before-read |
| `app/repositories/` | Allowlisted MongoDB queries, validators and indexes |
| `app/templates/`, `app/static/` | Shared Jinja components, organised tokens/CSS and progressive enhancement |
| `worker/` | Restricted generic notification process |
| `tests/unit/`, `integration/`, `security/`, `browser/`, `fixtures/` | Policies, real replica-set behaviour, negative journeys and synthetic data |
| `infrastructure/`, `scripts/` | Isolated dependency configuration, setup and maintenance |
| `docs/` | Requirements, architecture, decisions, risks, evidence and AI record |

Directories are placeholders, not importable application modules. Add code only in
its authorised stage. Keep secrets, local data, dumps, backups and `.venv` excluded.

## Primary documentation consulted

These mutable pages were checked for planning; recheck before package selection.

  supported Python range and environment isolation; Flask does not by itself

- [Authlib Flask integration](https://docs.authlib.org/en/latest/oauth2/client/web/flask.html)
  and [HTTP client documentation](https://docs.authlib.org/en/stable/oauth2/client/http/index.html):
  OIDC/PKCE integration capability. Full secure configuration is future work.
